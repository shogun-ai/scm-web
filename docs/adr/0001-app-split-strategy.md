# 0001. App.jsx хуваах стратеги

Төлөв: Батлагдсан
Огноо: 2026-10-07

## Нөхцөл байдал

`frontend/src/App.jsx` нь 1601 мөр бүхий монолит файл бөгөөд дотроо 7 inline page компонент, 3 inline utility компонент, 5 inline data массив, routing logic, state management, UI rendering бүгдийг агуулж байна. Энэ нь:

- Кодын уншигдах байдлыг муутгаж байна
- Шинэ feature нэмэхэд эрсдэлтэй (нэг файлд 14 нөхцөлт ternary chain)
- AdminPanel (3273 мөр), LoanRequest (936 мөр) зэрэг зочдод шаардлагагүй компонентууд initial bundle-д оруулагдаж, performance муудаж байна
- Тест suite байхгүй, production сайт (www.scm.mn) учир regression эрсдэлийг хамгийн бага байлгах шаардлагатай

## Авч үзсэн хувилбарууд

### Хувилбар A: Incremental Extraction (алхам-алхмаар)

Data, hooks, context, sections, pages-ийг 10 алхамаар тусдаа файлд гаргана. Алхам бүр тусдаа commit, build шалгалттай. Одоогийн custom routing хэвээр.

### Хувилбар B: Big-Bang Restructure (нэг удаагийн задлалт)

Бүх 1601 мөрийг нэг PR-ээр шинэ файлын бүтцэд шилжүүлнэ.

### Шалгуурын харьцуулалт

| Шалгуур (жин) | A: Incremental | B: Big-Bang |
|---|---|---|
| Бизнесийн үнэ цэнэ (15%) | 7/10 — ижил эцсийн үр дүн | 7/10 — ижил |
| Эрсдэл (30%) | **9/10 — алхам бүрийг тусдаа шалгана** | 3/10 — 1601 мөр нэг дор хөдөлнө |
| Хөгжүүлэх хугацаа (15%) | 6/10 — 7-10 хоног | 8/10 — 4-5 хоног (coding) |
| Засвар үйлчилгээ (15%) | 8/10 — жижиг PR, review хялбар | 5/10 — 2000+ мөр diff нэг PR |
| Буцаах боломж (20%) | **10/10 — алхам бүрийг тусдаа revert** | 2/10 — бүгдийг буцаах |
| Багийн ур чадвар (5%) | 8/10 — аажмаар сурч, дасна | 6/10 — бүгдийг нэг дор ойлгох |
| **Жинтэй нийлбэр** | **8.4** | **4.6** |

## Шийдвэр

**Хувилбар A: Incremental Extraction сонгогдов.**

### Шалтгаан

1. **Тест suite байхгүй.** Тест байхгүй орчинд нэг удаагийн том өөрчлөлт хийх нь эмнэлгийн шинжилгээгүйгээр мэс засал хийхтэй адил. Алхам бүрийн дараа `npm run build` + `npm run lint` + гар тестээр шалгаж, production руу итгэлтэй deploy хийнэ.

2. **Production сайт.** www.scm.mn нь Solongo Capital ББСБ-ийн үйл ажиллагааны сайт. Бүх хуудас нэг дор эвдрэх эрсдэлийг авах боломжгүй.

3. **Rollback.** Алхам 5-д section гаргахад алдаа гарвал зөвхөн тэр алхмыг revert хийнэ. Big-Bang-д бол бүх ажлыг буцаана.

### Хэрэгжүүлэх дараалал (10 алхам)

| # | Алхам | Эрсдэл | Шалгалт |
|---|---|---|---|
| 1 | Data файлд гаргах (`data/*.js`) | Бага | build + lint |
| 2 | Utility/hooks файлд гаргах | Бага | build + lint |
| 3 | AppContext үүсгэх, state шилжүүлэх | **Дунд** | build + бүх nav, scroll гар тест |
| 4 | React.lazy нэмэх (Admin, Loan, Trust, Onboarding) | Бага | build + lazy comp нээгдэх тест |
| 5 | Sections файлд гаргах | Дунд | build + visual шалгалт |
| 6 | Pages файлд гаргах | Дунд | build + бүх page нээгдэх тест |
| 7 | Navbar тусдаа файлд гаргах | Бага | build + nav тест |
| 8 | Шинэ хуудсууд нэмэх (Privacy, Terms, 404) | Бага | build |
| 9 | SEO (react-helmet-async) | Бага | build + title шалгах |

## Үр дагавар

### Эерэг
- App.jsx 1601 мөр -> ~200 мөр болно
- Initial bundle-аас ~120-175 KB (gzip) хасагдана (React.lazy-ийн ачаар)
- Шинэ feature нэмэхэд аюулгүй, ойлгомжтой файлын бүтэц
- Алхам бүр тусдаа deploy хийгдэж, regression-ийг эрт илрүүлнэ

### Сөрөг
- 7-10 хоног шаардана (Big-Bang-аас 3-5 хоног удаан)
- Олон PR, code review ачаалал нэмэгдэнэ
- Заримдаа хуучин pattern хэвээр үлдэж болно (100% "цэвэрхэн" биш)

### Эрсдэл
- R1: AppContext шилжилтийн үед props нэр өөрчлөгдвөл UI эвдрэнэ -> Context value-ийн нэршлийг одоогийн prop нэрстэй яг ижил хадгалах
- R3: Section гаргахад scroll anchor (#about-intro) алдагдах -> Section id-г яг хэвээр хадгалах
- R5: lucide-react CJS alias устгахад icon render алдаа -> Build шалгалт, шаардлагатай бол alias буцаах
- R7: Theme system (overlay, isLight) section рүү шилжихэд алдагдах -> getSectionBackgroundStyle-ийг context-ээр дамжуулах
